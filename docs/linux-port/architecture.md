# Архитектура порта для Kubuntu

## Цель

`linux/` — экспериментальное самостоятельное companion-приложение для KDE Plasma. Оно реализует edge-deck модель: узкую цветную плашку у правого края, веер вкладок, полноразмерную заметку, архив и быстрый ввод. Основная поддерживаемая поставка проекта — плазмоид из `plasmoid/package/`.

## Компоненты

- `linux/qml/Main.qml` отвечает за три состояния интерфейса, диалоги быстрой записи и библиотеки.
- `linux/src/notystore.*` хранит все заметки в SQLite и единолично изменяет данные.
- `linux/src/appcontroller.*` регистрирует действия в KDE GlobalAccel и размещает меню в системном трее; `linux/resources/noty.svg` — его независимая от темы пиктограмма.
- `linux/src/main.cpp` связывает C++-контроллеры с QML.

## Данные и безопасность

Данные лежат в `~/.local/share/Noty/`: база `notes.db` и файл ключа `note.key` с правами только владельца. Тело каждой заметки хранится как `nonce(12 байт) + ciphertext + GCM tag(16 байт)` и шифруется AES-256-GCM через OpenSSL. Заголовок, цвет и даты остаются незашифрованными, чтобы показать список без расшифровки каждого тела.

Формат ciphertext использует структуру AES-GCM combined; путь и идентификатор приложения относятся только к Linux companion-приложению. Автоматическая миграция данных из других программ не заявляется: импорт требует отдельной проверки на реальных экспортированных данных.

## Сборка и запуск

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
./build/noty
```

Чтобы установить для текущего пользователя и получить запись в меню приложений KDE:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX="$HOME/.local"
cmake --build build --parallel
cmake --install build
```

Установка кладёт исполняемый файл в `~/.local/bin/noty`, desktop-файл — в `~/.local/share/applications/` и иконку — в стандартный каталог иконок пользователя.

Зависимости: Qt 6.8+ (`Core`, `Quick`, `QuickControls2`, `Sql`, `Widgets`), KDE Frameworks GlobalAccel, SQLite Qt driver и OpenSSL. На текущей Kubuntu они обнаружены до начала разработки.

## Сочетания и ограничения Wayland

Зарегистрированы `Meta+Alt+N` (новая заметка), `Meta+Shift+Space` (быстрая запись), `Meta+Alt+A` (все заметки) и `Meta+Alt+L` (архив). KDE GlobalAccel поддерживается и в Plasma Wayland; набор можно перенастроить в системных настройках KDE.

Wayland не даёт обычному приложению глобально отслеживать позицию указателя вне его окна. Поэтому раскладывание веера гарантированно срабатывает при попадании указателя в плашку, а не за несколько пикселей до неё. Это платформенное ограничение, не ошибка хранения или интерфейса.

Кроме того, KWin на Wayland по протоколу может проигнорировать координаты обычного окна и показать его по центру. Для edge-deck это неприемлемо: до создания `QApplication` порт автоматически выбирает установленный Qt XCB-плагин (XWayland), если пользователь сам не задал `QT_QPA_PLATFORM`. После создания `QQuickWindow` C++ берёт `QScreen::availableGeometry()` и повторно закрепляет окно справа после каждого изменения размеров или экрана. Это надёжнее первого вычисления в QML, когда attached `screen` ещё может отсутствовать.

На текущей Plasma XWayland сообщает рабочую область в логических `1920×1080`, а Qt — физические `2560×1440`. Координаты для видимого X11-окна поэтому нужно сверять с логической рабочей областью KWin: плашка закрепляется на `x=1908` при ширине `12`.
