# Визуальная проверка

После каждого изменения внешнего вида QML обязательны не только исходные контракты, но и два снимка: детерминированный стенд и текущее состояние Plasma.

## Автоматический стенд

Команда `npm run test:plasmoid` создаёт семь снимков. `build/visual-snapshots/icon-system.png` показывает используемый набор Phosphor Regular: обычные действия имеют размер 16 px, а первичное добавление — 22 px; все варианты показаны на жёлтой и голубой поверхностях заметок. `build/visual-snapshots/plasma-icon-candidates.png` показывает по пять вариантов системных Plasma-иконок для архивирования и линеек; это визуальный контракт выбранных имён `archive` и `view-list-text`. `build/visual-snapshots/archive-confirmation.png` снимает настоящий компонент подтверждения очистки на светлой поверхности архива. `build/visual-snapshots/appearance-settings.png` рендерит реальную страницу настроек с Adaptive по умолчанию и системной типографикой. `build/visual-snapshots/pastel-card-contrast.png` показывает открытую пастельную карточку с её контрастной парой paper/ink; тест измеряет для неё контраст не ниже 4.5:1. `build/visual-snapshots/appearance-modes.png` показывает выбранную заметку и архив в Noty, Adaptive и Plasma на тёмном окружении; пиксельные проверки запрещают чёрную карточку или архив в Plasma. `build/visual-snapshots/notion-editor.png` показывает настоящий `NotionEditor`: quote rule, крупные rounded task-controls и bubble-menu над выделением. QML-тест дополнительно проверяет пиксели `x`: центр должен иметь единый серо-синий цвет, а угол обязан оставаться прозрачным. Это ловит прежнюю регрессию со сплошным квадратом. `tst_NativeMarkdownTasks.qml` подтверждает базовую интерактивность GitHub task list у самого Qt `TextArea`; `tst_RichEditor.qml` проверяет дополнительный слой `NotionEditor`, который передаёт действие крупного control в единственный Markdown store. `tst_ThemeContract.qml` фиксирует Adaptive как значение по умолчанию, 12 px как минимум системного шрифта и явное включение темы иконок Plasma.

## Снимок живого Plasma

После сборки, обновления пакета и перезапуска Plasma нужно открыть изменённое состояние виджета и выполнить:

```bash
npm run capture:plasmoid
```

Команда сохраняет полный снимок текущего рабочего стола в `build/visual-snapshots/desktop-latest.png`. Затем исполнитель обязан открыть оба PNG и проверить размер, цвет, оптическое выравнивание, hover/focus-состояния и отсутствие лишних подложек. Нельзя сообщать о визуальной готовности, если снимки не были просмотрены. Каталог `build/` исключён из Git.

Если на рабочем столе открыта не та поверхность, сначала нужно привести виджет в проверяемое состояние: карточка, архив, веер или настройка. Полный снимок может содержать другие окна пользователя и остаётся только локальным артефактом.

## Обязательная последовательность

1. Запустить `npm run test:plasmoid` и `npm run docs:check`.
2. Собрать проект, обновить `com.victor.noty` и перезапустить `plasma-plasmashell.service`.
3. Открыть изменённое состояние и запустить `npm run capture:plasmoid`.
4. Просмотреть `notion-editor.png`, `icon-system.png` и `desktop-latest.png`; при дефекте вернуться к правке.
5. Сравнить исходный и установленный QML по SHA-256 и проверить свежий журнал Plasma.

Для интерактивных иконок дополнительно проверяется статический контракт: у общего `NotyActionButton` и самостоятельных зон должны присутствовать `Qt.PointingHandCursor`. Это ловит регрессию, когда часть действий снова начинает показывать обычную стрелку.
